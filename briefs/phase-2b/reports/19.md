## What changed and why

All in `tools/search.mjs` unless noted; each is a rule about the query or the data, none names a query or an entry.

1. **Mapped entries are readable (prior).** An entry with mapped pages gets the readable prior 1.08 even when it has no
   llms.txt. `search_resources` already shows such an entry as `pages:N` instead of `unreadable:`, but `prior()` still
   gave it 0.85, the penalty for "nothing to read". cta.gallery (504 mapped CTA examples) and navbar.design (29) had
   0.85 and the One Page Love pages, whose site has an llms.txt, had 1.08: a 27 % gap on a near-tie. This one change:
   tuning MRR 0.725 → 0.759.
2. **An unreadable entry with a record is penalised less** (0.95 instead of 0.85). The record describes it fully, so
   whether the server can fetch its pages matters less for ranking. Entries without a record keep 0.85. Old eval
   recall 0.983 → 1.000 (fontpair.co / Typewolf / Coolors-type near-ties); held-out MRR 0.697 → 0.715 (D → D+unread95).
3. **Elements an entry only lists rank at a sixth of the weight** (problem 1 and 3). A record lists every element an
   entry *shows*: a one-pager its hero, CTA, pricing and footer; a broad gallery or kit a dozen. Only the elements the
   entry's **name or summary** names (`elementsIn(name + summary)`, the same tagger the build uses) stay in `element`
   (weight 3); the others go to a new field `listed` (weight 0.5). They still match and still filter
   (`element:` filter reads `entry_elements`, unchanged), and `matched` shows them as `element`. Entries without a
   record are unchanged. `INDEX_SCHEMA` 5 → 6.
4. **A synonym counts no more than the typed word.** A synonym alt's word score is scaled by
   `min(1, idf(typed words) / idf(alt words))`. Before, "radix" (idf 5.3) scored more at weight 0.7 than "shadcn"
   (idf 2.1) at weight 1, so for "shadcn …" every Radix-based repo outranked the entries that say shadcn. Applies only
   when the typed words have postings, so Turkish aliases and the fuzzy fallback are untouched.
5. **A plain word counts 0.7 of a taxonomy concept** (element, variant, synonym, category, Turkish alias) when the query
   has one (problem 4). In "brand mark ideas for a new startup" the design concept says what is asked; "ideas",
   "new" and "startup" only describe it, and Y Combinator's "Requests for Startups" matched three of them.
6. **A `logo` synonym group** in `catalog/taxonomy.json` (`logo`, `brand mark`, `logomark`, `logotype`, `wordmark`) —
   query vocabulary, not records. Before the records, Logo System matched "brand mark" only through an X label ("logo
   systems, not just marks"); its record says logo / wordmark / brand identity. Note: `tools/metadata.mjs` builds its
   keyword spelling map from the synonym aliases too, so a later `bun tools/build.mjs` would spell a record keyword
   "brandmark" as "brand mark" (none exists today; the records themselves are untouched).
7. **`search_resources` takes each group's best strong hit first** (`tools/mcp.mjs`, problem 3). The caps were meant to
   "keep every group visible among the strong hits", but ~70 navbar components within a few points of each other
   filled the 10 slots before the first gallery example (#73, score 14.9 against a best of 17.1, well above the
   half-best "strong" line). Now each group's best hit ≥ half the best score is taken first, then the capped and
   uncapped passes run as before. Group order (by first appearance) is unchanged.
8. **`tools/eval.mjs`** also scores `tools/eval/judged-queries.json` against `tools/eval/judge-2026-10-12-b19.json`:
   recall@5 and MRR count a grade-2 hit, nDCG@5 uses gain 2^grade − 1 against the best grades judged for the query,
   per half; unjudged hits score 0 and are counted and printed.
9. **Tests** (`tools/search.test.mjs`): listed elements rank below named ones and still filter; a synonym counts no
   more than the typed word; a plain word counts less than a taxonomy concept; an unreadable entry with mapped pages
   gets the readable prior. All four fail on the old ranker and pass on the new one.

**Why D+unread95 and not a higher tuning row.** The name boost (`nb`) and the repo prior (`repo104`) score higher on the
tuning half, but each costs the old eval 1–4 queries of recall@5 (0.933–0.967) and the descriptive block one query,
so they fail the done-when; `D+nb10` is also better on held-out recall / nDCG, which I only saw at the end. k1 > 1.2,
per-field normalisation, keyword caps, counting record fields in doc length and a partial-record penalty all lose on
both evals (the coordinator's findings on doc length and per-field normalisation hold). The coordinator's
"page elements rank only when named" (pages only) is `elem-pageNamed` / `rd+pageNamed`: weaker than applying the rule
to every record entry.

elements, priors) touches only entries. Over the 153 eval queries, the top 20 items are identical for 81, the same

## Unsure / open

- **Named queries for a canonical site still miss**: "radix ui", "shadcn ui", "unicorn studio" (held-out) and
  "framer motion" (tuning) have no grade-2 hit; radix-ui-com is 108th for "radix ui". Cause: its name and domain match
  ("radix" tf 6, score 9.8) loses to repos that repeat "radix" in four fields (tf 11, 10.6) after saturation, plus
  the repo prior. I found the held-out cases only when reading the final misses, so I did not tune for them; an
  exact-name boost (query words = an entry's name words) is the obvious next experiment, judged on a fresh held-out
  set. The proportional name boost (`nb`) helps the judged eval but costs the old eval.
- **ui-shadcn-com for "shadcn component library"** is 96th entry (82nd before): its summary says "component collection
  and registry", never "library", and the canonical-vs-long-tail near-tie remains. The old eval still passes on
  21st.dev / shadcn.io.
- **Judging**: 19 judge agents over 6 rounds; I did not measure agreement between them (no item was judged twice).
  The pool is the union of 48 variants' top 10, so a variant that surfaced many new hits was judged on them, but
  hits that no variant ranked are unknown (the ideal DCG uses only judged hits).
- **Tie order**: same-score components (the same "Accordion" in several registries) are ordered by doc number, which
  differs between a prebuilt index (`tools/index.mjs` order) and one built in memory from `catalog/items/`
  (`loadItems()` order). The harness and the server therefore show a different representative for 11 of 83
  queries; both sets are judged. A deterministic tie-break by id would remove this but changes item order; left alone.
- **Taxonomy edit** (`logo` synonym): allowed by the brief as I read it (records, metadata, crawl, items, patterns
  and registry configs are untouched), but it is a vocabulary change the coordinator may want to review.
- **Prior 0.95 for unreadable record entries** is a small step away from "readable first"; with the records, ranking
  by description is what the eval rewards. Without it the old eval is 0.983 / 0.772.
- Search p95 rose from 9.4 to 12.0 ms (warm) — the per-concept idf sums; still well under 30 ms.
