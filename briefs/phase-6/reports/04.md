## Acceptance points

- **`list_pages`** resolves `ref` with `resolveItem`, validates `element`/`variant` with `checkFilters`
  (a bad variant answers `unknown variant "huge" for navbar. Variants: mega-menu, dropdown, …`), ranks with
  `S.rank(query, { scope: "items", registry: <entry id>, element, variant })`, prints one deep link per page
  (`- <name> · <url> · <kinds>`, `id:` only for code/gated), `limit` capped at 50 (default 20), `more: offset=N`
  when the ranking is longer. `sitemap.json` is read lazily per entry and cached for the process
  (`sitemapCache`); `- <name> · <url> · <kinds>` lines never include a page id.
- **No items, no `sitemap.json`:** `ToolError` — `anthropics/skills has no mapped pages yet (no items, no
  sitemap.json in the corpus) — open https://github.com/anthropics/skills in a browser instead.`
- **Fallback filter:** whole path tokens against the query words plus the element's taxonomy aliases
  (element id, aliases and, when a variant is given, that variant's id/aliases) — `accordion` matches
  `/particles/accordion` only, not `/particles/alerts`-style near misses.
- **Gallery examples:** `itemGroup` = `granularity === "example"` → `gallery`, else `access === "page"` →
  `docs`, else `code`; the same split drives `elementFacets` (`gallery` beside `code`/`gated`/`page`) and both
  count lines. The new group has its own cap (`ceil(L × 0.3)`, same as docs) and is titled "Gallery examples".
  Updated regex in the navbar test: `/^# navbar · \d+ components \(\d+ registries; \d+ need a licence\) · \d+ gallery examples · \d+ docs pages/`.
- **`search_components`:** the url line is now `if (i.url && (access === "page" || access === "gated" || granularity === "example"))`
  — a page or an example shows its url, everything else is unchanged.
- **Readable flags:** `entryFlags` drops `unreadable:<reason>` and appends `pages:<N>` for any entry with ≥ 1
  item; `get_resource` adds `mapped pages: N → list_pages("<id>")` next to the existing `mapped:` line, whose
  "N docs pages" now counts gallery examples separately (`mapped: 496 gallery examples → …`).
- **Ranking:** `prior()` = `(code 1.06 · gated 0.94 · page 1) × (local 1.04) × (auto ? AUTO_ITEM 0.92 : 1)`.
  Verified with a throwaway script that ranks seven queries twice — once with the index as-is, once with every
  `auto` flag stripped — and compares `score_with / score_without` per item: **5,522 auto pairs at exactly
  0.92, 26,006 non-auto pairs at exactly 1.0, 0 mismatches**. `itemRecord()` now copies `auto` into the index;
  `INDEX_SCHEMA` 2 → 3 so an index written before this change is rejected (`loadIndex()` → in-memory build)
  instead of silently ranking auto items like curated ones.
- **Tests:** `bun test ./tools` → **104 pass, 0 fail** (100 before). New tests: list_pages pages + bad variant,
  sitemap fallback (with and without a query), "no mapped pages" error, and `pages:N` vs `unreadable:`
  (`search_resources({query: "navbar design"})` → navbar-design `pages:29`, `{query: "supahero"}` →
  supahero-io `pages:573`, both sites have `reach.ok: false`; `get_resource({ref: "navbar-design"})` still
  reports `reachable: NO`).
- **Instructions/description:** `instructions` line 3 is `list_pages("<site id>") lists the pages and gallery
  examples mapped inside one site (its raw sitemap URLs when it has no pattern yet).`; the `search_resources`
  description names the new group and `list_pages`. `tools/list` stayed inside its 8 KB budget (6,806 B,
  +1.2 KB of headroom).

## Open problems

1. **"Gallery examples" is decided by `granularity`, not by access** (the brief's literal "give
   `granularity: "example"` items their own group"). Consequence: 1,380 registry examples with code
   (shadcn.io demo blocks, magicui examples) also move out of "Components" into "Gallery examples", and the
   count line's `components` bucket shrinks accordingly (navbar: 405 → 380). Pinning the group to
   `access === "page"` instead would keep them in "Components" (navbar: 405 components · 525 examples); the
   existing "every registry with a navbar" test passes either way (all 38 parents have a non-example item).
2. **`pages:N` is printed for every entry with ≥ 1 item, not only for entries that would have been
   `unreadable`** — navbar-gallery shows `llms.txt pages:496`. Read narrowly, only navbar-design (29 pages,
   no llms.txt) would get the flag. The wider reading advertises the mapped pages everywhere; both satisfy the
   brief's test.
3. **The plain `navbar` query no longer shows the navbar-design entry.** Its own example
   (`navbar-design/letude`, now in the "Gallery examples" group) outranks the entry and takes the last slot, so
   the answer shows navbar.gallery only under "Sites & repos". The `pages:N` test therefore uses
   `query: "navbar design"`, where both gallery entries are listed. Not a ranking bug — the example is a
   better hit than the site — but it changes what a bare `navbar` query shows compared to before this brief.
4. **Prefix fallback = the directory of each URL** (all path segments but the last, `"/"` for root pages), so a
   site with mixed depths lists e.g. `/particles 8 · /particles/input 2` at once. This is intentional
   (a 2-segment page and a 3-segment page group differently); a single-depth grouping would lose the
   `/docs/guide` vs `/docs/reference` distinction.
5. **The fallback test pins `sv-particles.vercel.app`** (11 URLs, no items). Brief 05 (pattern review) or a
   later adapter run could give it items/pattern; the test then needs re-pointing to another sitemap-only
   domain. It asserts the fallback shape, so it fails loudly rather than silently passing.
6. **`bun tools/index.mjs` rewrites `catalog/items/` as well as the index** (it re-runs `buildItems` over the
   shared corpus). Item totals were identical before/after (52,776 in 219 entries); the index grew 27.4 →
   27.6 MB only because item records now keep `auto` (16,299 items).
7. **`search_components` "example items show their url" is a no-op on today's data**: of the 4,137 example
   items, the 2,757 sitemap ones already have `access: "page"` + url, and the 1,380 registry ones have no url
   at all (they expose `install_url`). The rule is implemented so a source that starts publishing example urls
   shows them without another change.
8. Minor, deliberate: the non-element count line (`# N matches · … · X gallery examples · Y docs pages`) also
   gained the gallery bucket although the brief only named the element line; the `search_resources` footer
   gained `list_pages("<site id>") lists one site's pages` (~60 B, inside the 3 KB navbar budget).

### C — a skip file answers with its reason, not its sitemap

Before touching `sitemap.json`, `list_pages` reads the entry's pattern file (`patternFile(domain)` from
`tools/sitemap-items.mjs`); `{"skip": "…"}` answers one line and never dumps URLs (129 B for
`aereference.com`):

```
aereference.com has no component or example pages: After Effects tips, not UI examples — open https://aereference.com/resources
```

It is a `ToolError` (same class as "no mapped pages"), so `isError: true`; the test asserts the exact line and
that `raw sitemap URLs` never appears. 170 skip files exist, 143 of them have a `sitemap.json` in the corpus —
all of them are covered by this branch. A skip only applies while the entry has no items: an entry whose *other*
adapter produced items keeps listing those items.
