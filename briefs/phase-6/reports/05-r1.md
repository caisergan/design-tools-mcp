## Decisions worth recording

- **animateicons.in / blobatar.dev / circleloaders.dominikakissi.com** are component-adjacent but have no
  per-example URLs (single icon pages with no taxonomy element, one docs page with #anchors, one page with #anchor
  variants that `hrefs` drops). Skipped rather than emitting element-less noise.
- **bootstrapmade.com `/ {name}`** matches 180 of 227 sitemap URLs: 27 `/bootstrap-*-templates/` +
  `/website-templates/` + `/free-website-templates/` category listings and `/tools/`, `/premium/`,
  `/portfolio-website-builder/`, `/bootstrap-template-builder/` are excluded; `/` (root) and `/tools/<tool>`
  (two segments) never match. `/php-email-form/` is kept (a form component page).
- **beui.saura3h.xyz** points at the redirecting host: `--fetch-filters` stored the `/components` page it fetched
  (after the 301) with links resolved against `https://beui.saura3h.xyz/`, so item URLs are on the catalog's domain
  and redirect to beui.dev. `--check` warns nothing; 92/92 links matched.
- **animatereactnative.com** has no `urls_from`: `/animations` is client-rendered (`grep href="/post/` = 0 links);
  the sitemap already lists all 142 posts.

## Open problems

1. **`bun test tools/` reports 91 pass / 9 fail, all pre-existing and environmental.** The 9 failures are in
   `mcp.test.mjs` / `items.test.mjs` / `build.test.mjs` and need `catalog/items/`, which does not exist in this
   worktree (gitignored, written by `tools/build.mjs`, which this brief forbids running). `bun test
   tools/patterns.test.mjs` (the pattern validation path my files go through) is 27 pass / 0 fail, and
   `bun tools/patterns.mjs --check` loads and validates the four new patterns.
2. **acrobatreaderonline.com is unreachable from this host** (curl status 000, no sitemap.json, no way to see the
   homepage). Skipped as blocked; a retry from another network may be worthwhile.
3. **`bootstrapmade.com` element coverage is 3%** (6/180). That is inherent: template slugs are brand names
   (`arsha-…`, `clarity-…`); the pages are whole-site templates, so they carry no taxonomy element. Same shape as
   the existing `colorlib.com` auto pattern.
4. **Ambiguity — a whole-site template with `granularity: "page"`.** `bootstrapmade.com` template pages could
   arguably be `"example"`; I followed the `colorlib.com` precedent (auto pattern, `"page"`) for consistency.
   `acebuilder.ai` and `animatereactnative.com` are `"example"` because they are demo galleries.
5. **`animateicons.in` may deserve an `icon` element** rather than a skip — 1,170 indexable pages, currently no
   taxonomy id/alias matches them. Recorded here as a taxonomy question, not a pattern question.
