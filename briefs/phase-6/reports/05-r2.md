## Open problems

1. **dycomps.oimmi.com is a real block library we failed to index.** Its `sitemap.xml` holds 953 URLs
   (`/templates/<c-blocks|s-blocks|others>/<category>/<variant>`, e.g. `/templates/c-blocks/hero/hero1`) but the
   `<loc>` values are missing scheme+host (`https://templates/c-blocks/about`), so brief 01's host check rejected
   them and no `sitemap.json` exists. The site is Framer-style and no page server-renders links, so `urls_from`
   cannot reach them either. A one-line fix in `tools/sitemaps.mjs` (join host-less locs against the sitemap URL)
   plus a re-fetch would make a `/templates/{*}/{element}/{name}` pattern possible — worth handing to the
   sitemaps owner.
2. **cssnippets.shefali.dev, cuedesign.space, design-on-x.com, clipppy.com** are skipped for "no reachable URL
   source", not because they lack UI content. cssnippets' client routes (`/buttons`, `/cards`, `/checkbox`,
   `/dropdown`, `/forms`, `/hamburger`, `/inputfields`, `/loadingspinners`, `/masonry`, `/radio`, `/texts`,
   `/toggle`) were recovered from its JS bundle; if the coordinator wants them, the pattern file could list them
   but there is still no sitemap or filter page to feed `match` — it needs a hand URL list mechanism.
3. **design-on-x.com (MotionVault)** is an inspiration gallery (like the catalog's 60fps.design / godly.website
   entries). Its 10,501 sitemap URLs are X posts (`/<user>/status/<n>/`) plus inspiration categories; there is no
   element typing and no component page, so it is a skip. If inspiration archives are wanted as items anyway, a
   `/<author>/status/{n}` pattern over `/archive/` would produce them (they would all be element-less).
4. **Host mismatches**: `components.bridger.to` serves from `components.work` and `componentry.fun` from
   `componentry.dev`, so both sitemaps were dropped as `empty` by brief 01 and I used `urls_from` instead.
   The patterns stay correct if the corpus later gains cross-host sitemaps (the same templates apply).
   `componentry.dev`/`components.work` themselves are outside this batch.
5. **editorcn.vercel.app** has the weakest element coverage (14%): its components are editor/extension docs and
   only `table` is a taxonomy element. Kept as items because the catalog indexes component-library docs pages
   elsewhere (daisyui, gluestack); trivial to turn into a skip if the coordinator disagrees.
