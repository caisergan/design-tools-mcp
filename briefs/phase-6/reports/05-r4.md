## Open problems

- **`bun test tools/` has 9 pre-existing failures** (`catalog/items exists`, MCP navbar/search queries,
  `pinned navbars are items tagged navbar`, …). They are identical (91 pass / 9 fail) with this batch's
  28 files moved out of `catalog/patterns/`, so they come from this branch lacking generated
  `catalog/items` + `catalog/search-index.json`, not from this batch. `tools/patterns.test.mjs` is 27/27.
- **patttterns.net item URLs keep the corpus host.** The site 301s to `patttterns.com`, but the catalogue
  domain is `patttterns.net`, so items are `https://patttterns.net/patterns/…` (the redirect resolves).
  The 86 `/patterns/…` URLs the site's own sitemap lists but no category page renders server-side (JS
  "load more") are missing; a `sitemap.json` for this host (brief 01's job) would close that gap.
- **48 MB of filter HTML cached** for patttterns.net (22 Notion pages, ~2.2 MB each) — by far the largest
  filter cache in the corpus (`navbar.gallery` 6 MB), unavoidable for a Notion-rendered site whose index
  pages carry no links. Not committed; delete `catalog/corpus/sites/patttterns.net/filters/` to reclaim.
- **patttterns.net 59 % element coverage**; the rest are animation/interaction patterns ("139-transition-
  zoom-out-on-hover") whose names carry no taxonomy element — items are still searchable by name.
- **pryzm.design is a judgement call**: the gallery is decorative image backgrounds for websites, not UI
  components. Mapped to the taxonomy's `background` element with a fixed `element`, granularity `example`.
- **`mapsplatform.google.com`, `raylight.app`, `plane.so`** etc. have product-demo pages that an agent
  could confuse with examples (Google Maps `/demos/*`); treated as product/marketing per the brief's
  "SaaS product site" case.
