## Open problems

- **`skiper-ui.com` items have no element (0%).** Its 106 components are genuine shadcn-ecosystem previews
  (`Anime js scrollbar`, `Parallax Image`, …), but every URL is numbered (`/v1/skiper1…106`) and the names
  live only in page `<title>`s — which the pattern language cannot read. `/components` (the real gallery) is
  client-rendered and links nothing statically, so no `elements_from` / `variants_from` page exists. Items are
  therefore named `Skiper1…Skiper106`; per-component element tags would need `catalog/overrides.json`, which is
  outside this brief's edit scope.
- **`shadcn-builder.com` drops 3 of 102 templates**: `insurance_claim`, `newsletter_signup` and
  `vendor_application` exist in two categories each, and the id is built from the last path segment only, so
  each keeps one item. The site's own sitemap lists only its 6 marketing pages; the template URL source is the
  template page’s global nav (any template page carries the same 102 links).
- **Root-only pages cannot be mapped**: `match: "/"` fails pattern validation (`template has no path segments`),
  so `shadcn-font-picker.vercel.app` (and `simply-buttons.vercel.app`, whose SPA exposes no links at all)
  are skips rather than 1-item patterns.
- **Three hosts cannot serve in-domain items at all**: `spark-ui-dev.vercel.app` (308 → `ui.selemon.dev`),
  `tailwindcomponents.com` (301 → `creative-tim.com/twcomponents`), `shop.ui8.net` (403) — the real content
  lives on other domains, which other batches may cover.
- `--check` compiles every pattern in the directory first, so a single invalid file prints
  `warn: template has no path segments` for unrelated checks; that warning disappeared once
  `shadcn-font-picker.vercel.app` became a skip.
