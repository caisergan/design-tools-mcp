## Open problems

1. **Snapshot of the 9 pre-existing test failures**: they need `catalog/items/*` + `catalog/search-index.json`,
   which are generated by `bun tools/build.mjs` — explicitly out of scope here, so `bun test ./tools` cannot
   be green in this worktree.
2. **`chrome-devtools-axi` truncates `eval` output at ~8 kB** mid-JSON (animista's 300 links). `renderPage`
   now passes `--full` and treats a truncated result as a skipped page; without it a big page silently
   yields no cache.
3. **dycomps coverage is 553/953**: the other 400 URLs are the 82 collection/category index pages and ~318
   leaf pages whose kind segment is not a taxonomy element (`about`, `gallery`, `portfolio`, `content` …).
   Mapping them would need element-less items, which was left out on purpose.
4. **animista has 1 % element coverage**: individual CSS animations (scale-up, blur-in …) are not taxonomy
   elements; the items are still name-searchable. Same shape for the tailark page templates (39 %).
5. **`/highlevel` on vibecodecomponents** rendered zero sections, so it was dropped from `anchors_from`; its
   rendered cache `filters/rendered-anchors-12.json` stays in the corpus (harmless, unreferenced).
6. **`--check` prints the "filter page … yielded 0 matching links" warning twice** (once from `loadFilters`
   with `quiet:false`, once from `cmdCheck`) — pre-existing duplicate, not touched.
7. **Notion pages** (`functional-snowflake-663`, `ozanoz`) cannot be mapped even with rendering: the Notion
   app shell exposes no own-domain links or sections.
8. **`tailwindtoolbox.com`** (→ windytoolbox.com) was not turned into a `source_domain` pattern because the
   target has no per-item pages (it is a directory of outbound links); if that ever changes the pattern
   belongs on the `tailwindtoolbox-com` entry with `"source_domain": "windytoolbox.com"`.
9. **Rendered-cache file naming** follows the existing `filters/` scheme instead of the brief's bare
   `rendered-<key>.json`: the cache holds both links and anchors for one job, so it is
   `filters/rendered-<urls|anchors|v|e>-<key>.json` (`rendered-urls-1.json`,
   `rendered-v-mega-menu.json`, `rendered-e-footer.json`, `rendered-anchors-1.json`), i.e. exactly the
   `-<key>` suffix of the matching HTML cache.
