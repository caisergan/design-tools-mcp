## After coordinator review

### Round 1 — names stop repeating path captures

`sitemapScan` builds the display name from the `{name}` capture — plus the `{element}`/`{n}` text of that same
path segment — prefixed by `{author}` when the template has one. An `{element}` captured in a segment of its own
contributes the element **label** as the suffix (the fixed-element label rule is untouched). Ids are built
exactly as before; the class-3 note of this round (qualifiers lost) is superseded by round 2.

### Round 2 — the rule is positional, and a name never repeats inside one site

Position decides what a capture in another segment does:

| capture | where | in the name |
| --- | --- | --- |
| `{author}` | anywhere | prefix |
| `{name}`, or `{element}`/`{n}` | its own segment | yes (the name of the item) |
| `{*}` / `{n}` | **before** the name segment | no — it groups the page (`c-blocks`, `dark`, `basic`) |
| `{*}` / `{n}` | **after** the name segment, or on the leaf | yes — appended as a qualifier (`history`, `one`, `02`) |
| `{element}` | a segment of its own | no — appended as the ` — Label` suffix |

A name that would still repeat inside one site is repaired deterministically (`finalizeNames`): the grouping
segments are appended, words the name already carries are skipped, and a counter is the last resort. Ids are
never touched; nothing of this leaks into the item JSON.
