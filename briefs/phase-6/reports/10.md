## Differences from the 09 drafts (and why)

1. **mobbin match made generic.** The draft's three literal templates (`/explore/web/{*}/{name}`,
   `/explore/mobile/…`, `/explore/sites/…`) put the *kind* in the id but not the *platform*, and web and
   mobile share the slug of the same kind (e.g. `deleting-deactivating-account` is both a web and a mobile
   flow): 242 of 1536 matched urls collapsed into existing ids. `match: ["/explore/{*}/{*}/{name}",
   "/explore/screens/{name}"]` captures the platform too, so all 1536 pages survive and the duplicated
   display names get their platform+kind appended (`Deleting Deactivating Account Web Flows`). `/colors/*`
   was dropped per the brief table (the draft had kept `/colors/meaning` + `/colors/brand`).
2. **designsystem.line.me gives 35 items, not ~70.** The 09 report's "70 component pages" counted leaf
   *links*: the rendered index holds 69 links matching `/LDSG/components/<cat>/<name>-en`, but only 35
   distinct pages (buttons 3, contents 5, indicators 4, inputs 9, navigations 7, overlays 6, systems 1),
   each linked both with and without a trailing slash. Re-rendered manually with an 8 s wait (the tool
   waits 3 s): 114 links, still the same 35 unique component pages. The pattern is right; the draft's
   count was a link count.
3. **raivcoo.com stays a skip.** The sitemap (2,780 locs, fetched) carries `loc/lastmod/changefreq/
   priority` only — zero `<video:title>`, `<image:title>`, `<news:title>` or `<title>` — and `sitemapScan`
   names sitemap items from URL captures only (`urls_from` contributes URLs, not link text; `loadFilters`
   discards the anchor text). Every one of the 2,773 `/media/<uuid>` items would display as a uuid
   (`0325ce63 9253 4264 828f Fd7dbdc5fc16`), which is useless for search. **Tool change that would fix
   it:** keep per-`<url>` titles in `sitemap.json` (`entryOf` in `tools/sitemaps.mjs`) and use them as the
   item name in `sitemapScan` when the URL carries no readable slug — or, for sites that publish none,
   a title-fetch option that reads the page `<title>` for uuid-shaped urls (the media pages do have one:
   `AgentArcade Promo video | Raivcoo`).
4. **mocku gives 117, not the draft's 1790** — the brief asked for the roots only.
5. **figcomponents gives 564, not 565** — one `sign-up%5C` link collision.
6. **beste/relume/cue match the drafts exactly** (3681 / 1757 / 54), and mocku/LINE/figcomponents item
   samples were verified against live pages with the catalog user agent (status + `<title>` only).

## Open problems

1. **`mocku.co` needed a corpus folder.** `buildItems` only visits domains that have a folder under
   `catalog/corpus/sites/`, so a `source_domain` pattern on a catalog domain without one scans nothing
   (the first `--check` showed 117 matched but 0 items). Created the (empty, gitignored)
   `catalog/corpus/sites/mocku.co/`; `figcomponents.com` and `designsystem.line.me` got theirs implicitly
   from the filter/render caches. A tool-side fix would be to visit every domain that has a pattern,
   not every corpus folder.
2. **mobbin's `/explore/screens/<uuid>` items** (120) are uuid-named by construction — same name-source
   gap as raivcoo, kept because the brief asks for that family. They are searchable only by url.
3. **mobbin names** for web/mobile twins grew a `Web|Mobile <Kind>` suffix from the tool's deterministic
   duplicate-name repair; ids stay `mobbin-com/<slug>-<platform>-<kind>`.
4. Rendered LINE leaves are SPA routes; only the url is stored, which is the contract for all items.
5. No other divergence: all six sitemap counts matched the 09 report on the first fetch, no host was
   blocked, and the 09-predicted item counts were hit for beste (3681) and relume (1757).
