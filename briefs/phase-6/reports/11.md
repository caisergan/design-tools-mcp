## How the hook chooses Scrapling, and how it falls back

`catalog/scrapling-hosts.json` maps a host to `{mode, enabled, note}`. A host matches itself and its `www.`
form, and only `enabled: true` ever uses Scrapling. Both Bun fetchers take the same seam, so everything around
it is unchanged:

* `tools/sitemaps.mjs` — `rawGet(url, via = scraplingClient)`, called by `request()`, so the per-host queue,
  the 500 ms interval (≤ 2 req/s), `MAX_BAD` blocking and the `MAX_BYTES` size cap behave exactly as before.
* `tools/patterns.mjs` — `get(url, via = scraplingClient)`, used by `--fetch-filters` (the 500 ms `PACE` stays
  on the Bun side).

`createScraplingClient` spawns **one `fetch.py --stdin` child per host** and speaks one URL per line in, one
JSON line out. That keeps one interpreter, one scrapling session (one browser in `stealth`/`dynamic`, always
`headless=True`, `solve_cloudflare=True` only in `stealth`), one robots.txt cache and one ≥ 1 s per-host pace
for the whole run — a 190-page crawl costs one process, not 190. `fetch.py` writes each body to
`<out-dir>/<n>.body` and answers `{url, final_url, status, bytes, file, challenge, content_type, error?,
too_large?}`; the client reads the body back and hands it over in the shape the caller already expected
(`{ok, status, type, body}` in `patterns.mjs`, `{url, status, bytes, text}` in `sitemaps.mjs`, gunzipped the
same way as a `fetch` body).

Fallback, in order:

1. **Host not enabled / not listed** → the client answers `null`, the caller does plain `fetch`: no spawn, no
   warning. `tools/scrapling.test.mjs` pins this for a disabled host and an unlisted host.
2. **Enabled but unusable** (venv or `fetch.py` missing, spawn throws, child dies, or it stops answering —
   `--timeout` 120 s) → **one** warning per run, `scrapling: … — falling back to fetch`; that host is dropped
   for the rest of the run and its URLs go through plain `fetch`. The run never crashes; a JSON line that
   *comes back* is an answer, not a failure.
3. `{status: 0, error: "robots"}` is never retried with `fetch` — a robots.txt-disallowed URL is reported, not
   bypassed (`sitemaps.mjs` returns it as `{status: 0, error: "robots"}`, `patterns.mjs` fails that page and
   says why).

## `paginate`

```jsonc
{ "elements_from": { "button": "/buttons" }, "paginate": { "param": "page", "max": 80 } }
```

`validatePattern` accepts exactly `{param: non-empty query-parameter name, max: integer 1–500}` — a missing
param or max, a float, `0`, `501`, `null`, a string, an array or an unknown key is rejected. The option
applies to every `urls_from`, `variants_from` and `elements_from` job (never to `anchors_from`, which is one
page each) and to no other pattern option: `filterFile(domain, kind, key, page)` keeps the existing cache-name
convention (`filters/e-button.html`, `filters/e-button.2.html`, …), no page renaming for existing sites.

`--fetch-filters` (in the exported `fetchFilterJob`) fetches the first page at the job's path, then
`<path>?<param>=2`, `=3` … merged into any query the path already carries, caching each page next to the first,
and stops at `max` pages **or** at the first page that adds no new link matching the pattern — an out-of-range
page comes back empty (or repeats the last one) and ends the walk. The stop page is cached too, so a resumed
run stops at the same page. `loadFilters` reads every cached page of a job (up to `max(20, paginate.max)`), so
items keep the job's element/variant no matter which page listed them. Without `paginate` the old behaviour is
untouched (the page's own "next page" link, ≤ 20 pages).

## The challenge rule, before/after

Old rule (`probe.py`): one regex over the first 200 KB — `Just a moment...|cf-chl-|challenge-platform|
Attention Required|cf-turnstile|captcha-delivery|px-captcha|Access denied`. It matched the Cloudflare JSD
beacon (`/cdn-cgi/challenge-platform/scripts/jsd/main.js`) and i18n strings like "Access Denied" inside real
pages.

New rule, now in `probe.py` (`is_challenge`), `tools/sitemaps.mjs` (`isChallenge`) and, through the import,
`fetch.py`: a page is a challenge when its `<title>` is "Just a moment…" / "Attention Required…", **or** its
status is 403/503 **and** the body carries a challenge marker.

## Enabling a disabled host

No code change, by design — `land-book.com`, `ui8.net` and `saasframe.io` are fetched by the same two call
sites as `uiverse.io`, and both read `catalog/scrapling-hosts.json` at process start:

1. Set `"enabled": true` for the host in `catalog/scrapling-hosts.json` (its `mode` is already the minimal one
   that works: `http` for `land-book.com` and `ui8.net`, `stealth` for `saasframe.io`). `bun tools/sitemaps.mjs`
   and `bun tools/patterns.mjs --fetch-filters` now fetch that host through `fetch.py`.
2. That is all for the *transport*. Items still need the per-site data work every other site got:
   a `catalog/patterns/<domain>.json` pattern (`land-book.com` and `saasframe.io` have none yet; the draft
   patterns in `reports/09a.md` §2.2/§2.4 are the starting point), and for `ui8.net` a `kind: "site"` catalog
   entry — the catalog currently has only `page` entries for that domain, so items would hang off whichever
   product page `parentsByDomain` picks first. `shop.ui8.net` is a `skip` pattern today.
