## Detail per group

### Icons (rows 79–87)
- `ionic.io` — 2313 URLs, all product docs/blog/resources/support; `/ionicons` (+`/usage`, `/v1`–`/v4`) is the single
  Ionicons pack and already the entry's URL, so a pattern would only duplicate the parent item.
- `katu.com` — 500 URLs of TV news; the queue category comes from a news article, not a resource.
- `minoradventures.co`, `ui-resources.com`, `uipedia.design` — no per-set or per-guideline pages (blog, hub pages,
  SEO listicles).
- `nucleoapp.com` — the library is one app but the site splits it into 44 category collection pages plus named
  sets/free packs; explicit paths because there is no prefix family for them.
- `simpleicons.org` — one set rendered by one SPA page; `simpleicons.org/preview` is also client-rendered (empty
  `<title>`).
- `tabler.io` — `/icons` is the entry URL; `/icons/packages` is "Packages – Tabler Icons" install docs; the useful
  non-duplicate pages are the other asset libraries.
- `thiings.co` — every `/things/<name>` is one AI-generated 3D icon; `--suggest` (10 491 URLs) shows `/categories`
  listings as the only other group, so the site is the single-asset flood the brief excludes (and over cap anyway).

### Fonts (rows 88–104)
- `bestfreefonts.com`, `fontsquirrel.com`, `uncut.wtf`, `theleagueofmoveabletype.com`, `typewolf.com` — plain
  family-page patterns; only `/styles`, foundry/team profiles, site pages and top-10 listicles need excluding.
- `fontpair.co` — JS-rendered (every page returns the same `<title>`), the URL families are the only signal; the
  four font catalogues have no slug overlap, only `source-sans-pro` collides after slug normalization (one item lost).
- `fonts.google.com` — specimens plus the knowledge guidelines; the 18 `/knowledge/<topic>` section roots are
  listing pages and stay out (`/knowledge/{*}/{name}` only matches the article pages) — the 13 section roots
  (`/knowledge/glossary`, `/knowledge/using_type`, …) are not items.
- `fontesk.com` — one family per page, 13 528 of them: cap skip with the exact figure for the coordinator.
- `collletttivo.it` — sitemap structure (`/typefaces/<family>`) is unambiguous and the same families appear as
  confirmed font pages on other sites, but the host never answered plain curl, so no pattern was written.
- `follow.art` — Cloudflare 403, skip per the blocked rule.
- `dejiajetomobi.com`, `furniqo.framer.website`, `pierrickcalvez.com`, `rectangles.fm`, `typescale.com`,
  `font.thmanyah.com` — the row's "fonts" label comes from a single article, a template demo, a portfolio or a
  newsletter; none has font family pages.

## Verification
- `bun tools/patterns.mjs --check <domain>` run for all 26 rows; item counts, element percentages and samples in the
  table are those outputs (each pattern loads under the strict validator).
- Page kinds confirmed with `curl -s -A "Mozilla/5.0 (compatible; design-tools-catalog/1.0; +local)" <url>` and the
  `<title>`/`<h1>` only, e.g. `Work Sans Font Combinations & Similar Fonts · Typewolf`,
  `Chunk | The League of Moveable Type`, `Download Geist – UNCUT.wtf, free typeface catalogue`,
  `Microwave Oven 3D Icon — Free PNG Download`, `40 Products on Amazon for Designers` (the `/amazon` page that the
  typewolf exclude list covers).
- Element percentages are 0–7% because the icon/font/glyph pages carry no taxonomy element by design (brief 12);
  the few tagged items (e.g. tabler `/avatars` → `avatar`, nucleo `/icons/charts` → `chart`) come from the shared
  tagger, not from forcing elements into the patterns.
- No `catalog/corpus/` file was written (no filter downloads), nothing outside `catalog/patterns/` for these 26
  domains was touched, and `bun tools/build.mjs` was not run.
