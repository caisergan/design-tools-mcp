## 1. Sitemap pages fill a missing url

The attach branch in `sitemapScan`:

```js
if (taken.has(id)) {
  const it = taken.get(id);
  if (it.from === "registry" && !it.url) { it.url = url; urls_attached++; takenUrls.add(key); }
  skipped++;
  continue;
}
```

- The page still counts as `skipped` (it made no item) and `matched` as before; `urls_attached` is new.
- A registry item with a url already set is never overwritten; an `llms`/`sitemap`/`api` item with the id is
  never touched (no url, no rename, no access change). Registry item keeps its own name, elements and access.
- Field-level probe over all 4,171 shadcnblocks registry items: exactly 4,132 items changed, and the union of
  changed keys is `["url"]` — nothing else moved. 0 items that already had a url were touched.
- Filter-derived anchors keep the old rule (only the sitemap/urls_from candidate loop attaches).

## 2. shadcnblocks

**File name / source_domain.** The catalog entry is `www-shadcnblocks-com`, but its `domain` field is
`shadcnblocks.com` — the same as the corpus folder (`catalog/corpus/sites/shadcnblocks.com/`), and
`parentsByDomain`/`loadSitemap` key by that domain. So the pattern is `catalog/patterns/shadcnblocks.com.json`
and no `source_domain` is needed (the brief's "domain `www.shadcnblocks.com`" does not match the catalog.json
entry).

**Template.** The brief's `/component/{name}` matches nothing: every one of the 2,104 `/component/…` pages is
`/component/<category>/<slug>` (two path segments after `component`), so a two-segment template has 0 hits.
The registry's own naming scheme decides the rest:

| template tried | pages matched | urls attached | new items |
| --- | --- | --- | --- |
| `/block/{name}` + `/component/{name}` | 2,028 (blocks only) | 2,028 | 0 |
| `/block/{name}` + `/component/{element}/{name}` | 3,285 | 2,028 | **1,257** — ids like `accordion-form-1-accordion` (leaf-element order) match no registry id |
| `/block/{name}` + `/component/{author}/{name}` | **4,132** | **4,132** | **0** |

`/component/<cat>/<leaf>` ids the engine builds as `slug(cat-leaf)`, which is exactly the registry's component
name (`accordion-accordion-form-1` ↔ `/component/accordion/accordion-form-1`). `{author}` (a one-segment capture:
tailark uses it for its theme segment) is the only placeholder that keeps the `<category>-<name>` order; a fixed
`element` or `{element}` would need the category to be a taxonomy element (many are not: `bento-tile`,
`announcement`, `aspect-ratio`, …) and would create spurious items with reversed ids.

**`/component` overlap** (last path segment vs registry slug): **0 / 2,104** — the leaf slugs use a different
naming scheme (`chart-area-axes`). As `{category}-{leaf}` pairs: **2,104 / 2,104**. `/block/<name>`: **2,028 /
2,028** leaf names == registry slugs.

**Numbers** (`bun tools/patterns.mjs --check shadcnblocks.com`, 4,850 sitemap URLs):
