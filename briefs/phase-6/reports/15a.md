## 1. shadcn.io — pattern `catalog/patterns/shadcn.io.json`

Registry: 7,999 raw items (152 names repeated across types) → 7,847 catalog items, **all url-less**. The page slug
of every family is the registry name, so all 13 templates are `<literal family>/{name}` and the id the engine
builds is the registry name itself.

| shape | pages | attaches | what it is |
| --- | --- | --- | --- |
| `/blocks/{name}` | 6,157 | 6,147 | block preview page, slug == registry name |
| `/view/{author}/{name}` | 6,156 | 0 | live-preview twin of the same block (`<title>… — Live Preview`) |
| `/examples/{name}` | 1,104 | 1,103 | component example (`registry:example` items) |
| `/ui/{name}` | 83 | 64 | shadcn ui docs page |
| `/components/{name}` | 59 | 53 | component page |
| `/text`,`/background`,`/shaders`,`/charts`,`/ai`,`/button`,`/hooks`,`/theme` | 100/100/57/53/51/35/34/59 | 99/100/48/53/46/35/34/59 | effect/chart/ai/button/hook/theme families; `/theme/<name>` is a `registry:style` item (e.g. `/theme/vercel` ↔ `vercel`) |

**Shape preference (the extra's question).** `matchUrl` uses the *first* template in `match` order that matches the
URL (`compiled.templates.map(...).find(Boolean)` in `tools/sitemap-items.mjs`), but that only decides how a single
URL's captures are read. For **two different pages of one id** the winner is the **first page in sitemap order**:
the candidate loop walks `sitemap.urls` and a registry item that already has a url is never overwritten. In the
corpus the `/blocks` pages sit in `sitemap-docs.xml`, the `/view` pages in `sitemap-view.xml` (later), so for the
6,052 items that have both pages the `/blocks` page always wins — the `/view` template attaches 0 today and is
kept only as the fallback shape if the pages order ever flips. Template order in `match` cannot change this.

**Things deliberately not matched** (all verified against the file):
`/icons/*` + `/icon/*` (34,299 URLs) are icon sets, not registry items; `/template*`, `/awesome/*`, `/tools/*`,
`/design/*` are the survey/listing families; `/docs/*` does not exist in the file (the sub-sitemap *named*
`sitemap-docs.xml` carries the block/example/tool pages). `/mcp/<name>` (52 pages) was dropped on purpose: it is
MCP-client setup docs and `cursor`, `warp`, `vs-code` collide with registry names — the real pages
(`/components/cursor`, `/background/warp`, `/theme/vs-code`) come earlier and win anyway, but the template would
have been a false-attach hazard. `/view/search` (one page) matches no template.

### The truncated sitemap (extra for 15a)

`https://shadcn.io/sitemap.xml` fetched once (not counted as a page): the index now lists **240** sub-sitemaps,
`sitemap.json` `.sources` has **100** (the index + 99 children, all status 200).

- **141 sub-sitemaps are not reached: every one is `sitemap-icons-*.xml`** (fluent, material-symbols,
  material-symbols-light, arcticons, ic, ph, mdi, solar, tabler, hugeicons, …) — icon libraries, none of them
  would carry component pages. The 18 non-icon sub-sitemaps in the index (main, docs, ui, icons, icon-tags,
  templates, the 8 `*-blocks`, view, awesome, design, examples) are all reached.
- The 50,000-URL cap cut *inside* the icon families: the last URL kept is
  `https://www.shadcn.io/icon/fluent-star-add-28-regular` (sitemap order = source order). The **80** sources after
  `sitemap-icons-fluent.xml` in `.sources` (material-symbols … stash) contributed no URL at all, and every one of
  them is an `icons-*` sub-sitemap — so no registry page was lost to the truncation. The file's budget is
  34,299 icon URLs (~69%) against ~15,700 non-icon URLs.

## 2. reui.io — pattern `catalog/patterns/reui.io.json`

Registry: 1,728 items (1,647 `registry:block`, 77 `registry:ui`, 4 hooks). Item id is the plain slug
(`reui-io/c-button-1`, `reui-io/app-shell-1`); the site's page leaf **is** the registry name
(`/components/button/c-button-1`, `/blocks/application/app-shell/app-shell-1`).

The id the engine builds is `<captured segment(s)>…-<leaf>`, and an `{author}`/`{*}` parent segment would put the
category *in front of* the id (`button-c-button-1`), which matches no registry item — so the pattern carries one
**literal** category-path template + `{name}` per category: 59 `/blocks/...` (4 segments, `{name}` = block variant)
and 74 `/components/<category>/{name}` (component variant, e.g. `/components/button/{name}` 61 pages).

- `/blocks/application/{name}` is **not** a template: those three pages (`event-calendar`, `gantt`, `timeline`)
  are category listings of the same word, and those items already have urls (`registry:ui`, llms docs).
- The 22 `/components/<base>` and `/docs/components/radix/<base>` pages are the same 22 components' other pages;
  their `/docs/components/base/<base>` pages are already the **llms docs urls** of the registry:ui items
  (`reui-io/alert` → `https://reui.io/docs/components/base/alert`), and a registry item with a url is never
  overwritten — the templates would attach 0, so they are not in the match list.
- Left out: `/icons/*` (30), `/template*` + `/templates/*` (21, real templates but the brief forbids the prefix and
  none is a registry name), `/docs/*` listings, `/legal/*`, blog-less static pages, and ~380 newer pages whose
  leaves are not in the registry snapshot (`c-time-picker-1`…, `chart-31`, `sheet-12`, `app-shell-22`, `pricing-*`,
  `compare-*`, `whiteboard-*`, `data-grid-base-8`) → no item with `attach_only`.

## 6. Unsure / worth knowing

- **`attach_only` = 0 items everywhere.** Every page family on these three sites is a page *of* a registry item;
  the 6,285 matched pages that attached nothing are a second page of an id another page attached first
  (shadcn.io's 6,156 `/view` twins, its 9 block/example names) or pages with no registry twin — newer than the
  registry snapshot (reui.io `c-time-picker-1`…, shadcn.io `an-interactive-bar-chart`), family overviews
  (shadcncraft.com `avatar-upload`, reui.io `/components/pro-application/*`-style names), docs and listings. If any
  of those should become items, that is a survey decision, not a pattern change.
- Hooks: reui.io and shadcncraft.com ship 4 hooks each (`use-file-upload`, `use-mobile`, …) that the sites do not
  document on their own; shadcn.io's 34 hooks all attach via `/hooks/<name>`. The undocumented ones stay url-less.
- shadcn.io's sitemap is truncated (see §1). A refetch could reach pages the current file cannot — the
  `/mcp/<name>` exclusion (editor setup pages colliding with `cursor`/`warp`/`vs-code`) must stay out either way.
- Inert templates were left out, not carried: shadcn.io keeps `/view` (its blocks twins win today), while reui.io's
  `/components/<base>` and `/docs/components/{base,radix}/<base>` were not added at all because those 22 ids already
  carry llms docs urls (§2). Nothing attaches twice — a registry item keeps the first url it gets.
