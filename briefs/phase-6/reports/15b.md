# Brief 15b — Page URLs for the b-batch registries — Report

Branch `phase6/registry-urls-b`, 2026-10-10. 28 pattern files added under `catalog/patterns/`, no code changes.
Every pattern is `"status": "hand"`, `"granularity": "variant"`, `"attach_only": true`; `bun test ./tools` passes
(175 pass, 0 fail). All 28 `--check` runs were compared against an offline simulation of the engine's id/attach
rules — they agree on every site, so the numbers below are the committed patterns' real effect.

## Summary

- **28 / 28 sites** got a pattern file; none needed `skip`, none needed `attach_only` dropped.
- **1,335 urls attached** to registry items across the batch, **0 new items** (the 1,500 budget is untouched).
- 3,944 registry items in the batch; 1,659 end with a url (324 already had one from llms/docs pages), 2,285 stay
  without — each site's reason is in the table.
- 84 attached pages spot-checked (3 per site): 83 × `200` with the component's title, 1 × `404`
  (ui-layouts, see §4); robots.txt fetched and checked for all 28 first — no template matches a disallowed path.

## Method

Per site: registry names (`jq -r '.items[].name'`) next to the sitemap paths, then a template per path shape whose
id matches the registry's naming (`<entry id>/<slug(captures)>`; `{author}` is the only capture prepended to the
name segment, so `/x/{author}/{name}` is the shape for `<a>-<b>` names and literal prefixes are used wherever a
category segment is *not* part of the name). `attach_only` keeps unmatched pages from making items; a page only
ever fills a url. Survivors were confirmed with `bun tools/patterns.mjs --check <domain>`.

## Notes, decisions, uncertainties

- **No `attach_only` was dropped.** On every site the pages without a registry twin are listings, docs, demo
  items or a second name for an existing item, so 0 new items were made (brief budget 1,500).
- **Estimates in the batch table vs the names matched.** Several sites have more item names with a matching page
  than the table's "fillable" number (chanhdai 49 names match, 12 attach; uibeats 55/10; kokonutui 46/9;
  ui-layouts 49/15→9; ui.shadcn 62/6) because the llms adapter already attached docs urls to the rest; `--check`
  counts only the still url-less ones.
- **Registry names with `/`.** pdfcn's items are `takumi/…` / `forme/…`; the engine slugs the name to
  `takumi-…` for the id, which is exactly what `/docs/components/{author}/{name}` builds — 68/79 attach.
- **One-segment template.** shadcnexamples is `match: ["/{name}"]`; under `attach_only` it can only fill an item
  whose slug equals a top-level page's slug (68 of 89 pages do).
- **Repeated ids across URL families** (sv-blocks `/preview/...` vs `/preview/mist/...`; ui.8starlabs
  `/docs/components/...` vs `/llm/components/...`; uibeats `/docs/...` vs `/playground/...`; ui.shadcn
  `aria`/`base`/`radix`): both/all templates are listed, each produces the same id, and the page that comes
  **first in sitemap order** wins (`matchUrl` picks the first matching *template* per URL, but there is no
  ordering across URLs). For ui.shadcn that means whichever framework mirror appears first in the sitemap fills
  the url — only the 4 aria-only and 2 react-only items were url-less, so the choice never mattered here; if the
  catalog later wants radix pages preferred, only the radix template should be kept.
- **remocn `/showcases/{name}`** was added after the first survey pass missed it (2 items: `remocn-ui`,
  `signup-flow`); 104 attached is the final number.
- **8bitcn page titles ≠ item names for some blocks** (`advanced3` is a "Newsletter" block, `timeline3` a
  "Zigzag Roadmap"): the page is still that registry item's page, so the attach is right.
- **ui-layouts excluded paths** is the one place where the pattern knowingly ignores sitemap urls (§4).
- **Request discipline.** 3 attached pages per site were fetched for the spot checks (robots.txt extra,
  uncounted), plus the ui-layouts dead-link investigation (§4) and one discarded retry of the spot-check curl
  loop whose title parsing was broken — the numbers above come from the re-run.
- Not done on purpose: nothing outside `catalog/patterns/` + this report was touched; no `build`/`index`/`fetch`
  runs.
