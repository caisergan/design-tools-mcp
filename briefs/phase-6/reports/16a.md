## The format: one optional key added
**`"exclude": [regex, …]`**: registry names (before rewrite) that have no page of their own. They are never
fetched, are recorded as `null` and are counted as `excluded`. I added it because animate-ui has 260 `icons-*` items
whose only page is the `/docs/icons` gallery (`/docs/icons/<name>` is a 404). Without the key, each one costs a
404 request on every fresh run, and a rewrite can't drop a name. The key is optional, so configs written by
16b–d in the brief's format validate unchanged. Everything else follows the brief: `templates`, `rewrite`, `types`,
`status`, `note`, `skip`. Unknown keys are an error.

## Design decisions
- **Registry name** is `item.slug`, falling back to the id after `<entry id>/`, as the brief says.
- **`rewrite`** runs each pair as `name.replace(new RegExp(re, "g"), to)`, in order. The global flag only matters
  for unanchored patterns such as `["_", "-"]`. Anchored ones (`^…$`) behave the same either way.
- **Encoding**: the rewritten name is encoded per `/`-part, so a rewrite may add path segments (animate-ui:
  `components/radix/tabs`). A rewrite that produces an empty part, `.` or `..` gives no candidate, so it can't
  climb out of the template. The validator also requires `{name}` to sit after the origin (never in the host).
- **Pass rule (`judge`, pure)**:
  - The final status is 200 and the content type is `text/html` or `application/xhtml+xml`.
  - The final url is on the candidate's host (a `www.` difference is allowed) and has the same decoded path (a
    trailing slash is allowed).
  - Any other path is a miss: the site root, a listing, or another component. kibo's `/components` really
    redirects to `/components/avatar-stack`, and a test covers that case.
  - A `<title>` equal to the soft-404 probe's title is a miss.
  - A title that says `404` or `not found` is also a miss, unless the registry name itself contains 404 or
    not-found (block registries have "404 page" blocks).
- **Soft-404 probe**: one per directory a candidate lives in, meaning the template filled with the rewritten name
  whose last `/`-part is replaced by `zz-design-tools-probe-404`. For a plain name that is exactly the brief's "each
  template once"; with animate-ui's rewrite it probes each `components/<group>/`, because catch-all routes can differ
  per directory. A probe that answers 200 at its own path marks the template **soft**, and candidates are compared
  by title. The template counts as **blind**, and all its candidates as misses, when that 200 page has no title,
  echoes the probe name in its title, or is disallowed by robots.txt.
- **Miss vs. retry**:
  - A definite miss (404/410, other 4xx, not html, wrong path, soft-404, robots) is recorded as `null`.
  - Status 0, timeout, 403, 408, 425, 429 or 5xx (on the candidate or its probe) is not recorded, so the next run
    tries that item again.
  - If an earlier template is unknown, a later template's hit is never taken: the item waits for the next run, so
    template order is respected.
- **robots.txt**: read once per host. Rules come from the `*` group plus any group naming our UA token; the
  longest match wins and Allow wins a tie; `*` and `$` are supported. A robots.txt that answers html (an app
  shell) or 4xx means no rules. A 5xx, 403/429 or timeout on robots.txt stops the host for the run (Google's
  reading of an unreachable robots.txt).
- **Fetching**: same backend as `tools/patterns.mjs`: the Scrapling client for an enabled host, plain `fetch`
  with `UA` from `tools/sitemaps.mjs` otherwise. 15 s timeout, redirects followed.
- **Pacing and blocks**:
  - One request per 500 ms per host, ≤ 4 domains in flight (`pool`).
  - A host that answers 403/429 three times in a row is stopped for the run; its remaining items are not recorded.
  - Each page and probe url is fetched once per run, even when several items share it (group pages).
- **Per-domain counts**: in a parallel run, each domain counts its requests and stopped hosts through
  `fetcher.scope()`. My first pilot run used deltas of one global counter and printed nonsense (kibo "223
  requests" for 40 items). That is fixed and covered by a test.
- **Cache** (`registry-urls.json`):
  - Fields: `{ checked_at, config_hash, results, stats: { targets, urls, nulls, unchecked, last_run } }`.
  - `config_hash` covers `templates`, `rewrite`, `types` and `exclude`, but not `note` or `status`.
  - Results of ids that left the registry are dropped.
  - The tool works out url-less items with `buildItems(…, { only, templateUrls: false })`. Leaving out the
    tool's own cache matters: otherwise `--force` or a changed config would never recheck items the cache had
    already filled.
- **Build fill**: only `from: "registry"` items without a url take `results[id]`, and only when it is an
  http(s) string. A missing cache is silent; a broken one is a warning and counts as no cache.
- **Progress**: `--verify` prints a start line per domain and a line every 100 items on stderr, because 16b's
  batch has a site with 4,002 items (~35 min at 2 req/s).
