## Things I was unsure about

1. **Group pages.** uiable (variants → component page), bundui (demo files → base component page), magicui and ui.8starlabs
   (example items → component page), smoothui (blocks → `/docs/blocks/<category>`, the page carries its blocks) follow the
   brief's group-page allowance and say so in `note`. The two-phrasing edge is smoothui's category page (a category listing that
   shows each block) — if the coordinator counts that as a "listing", those 34 links should be dropped; same shape as uiable's
   `/blocks/<category>` (60 items). flightcn's `/blocks` gallery (all 11 blocks on one page, per-block anchors) was *not* treated as
   a group page — it mixes unrelated components, like the brief's icon-set example; those 11 stay url-less.
2. **Soft-404 sites.** uiable, heroicons-animated, ui.meta-cloud-api.site and vengenceui answer unknown paths with 200 + a generic
   title. For uiable/heroicons the engine needs the soft-404 title guard to work as specified (real pages have their own titles);
   for meta-cloud/vengenceui everything would be a miss, hence skip.
3. **Counts.** shadcn-ui-blocks' table count 4002 includes 99 `registry:item` `og-image-*` items the default types filter drops
   (engine sees 3903, all fillable). smoothui: 40 typed url-less items, not 41.
4. **fluid-functionalism** pages carry a generic `<title>` ("Fluid Functionalism") — identity was verified via `<h1>` and the
   registry's own `docs` field; the engine's pass rule (status/content type/final url) still holds because the probe 404s.
5. **termcn/agentcn** moved domains (vercel.app → www.termcn.dev / www.agentcn.run). Templates use the new hosts directly; no
   `source_domain`/corpus sitemap was needed because the route is B.
