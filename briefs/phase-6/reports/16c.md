## Verification

- **The real engine** (16a's `tools/registry-urls.mjs` is not on this branch): extracted `phase6/registry-tpl-a`'s
  `tools/` into a scratch dir with this worktree's `catalog/` linked in and ran
  `bun tools/registry-urls.mjs --check <domain>` for all 18 domains. Every config **validates** (`config ok`) and
  the live check behaves as the table says: launchui 10/10, localmode 10/10, more-shadcn 10/10, shuip 10/10,
  sv-table 10/10, chatbot-kit 9/10, flexnative 9/10 (+1 unfinished/retry), shadcn-map 7/10, 1st-pouf 3/10 (sample
  drew the ui primitives that have no page), shadcnblocks 1/10 (sample drew the 27 families without a hub),
  tool-ui 2/10 (sample drew the 17 blocks assistant-ui dropped), and the two caveats: tailark 0/10 (soft-404
  probe "blind" — every slug page echoes the name) and ui.soralabs.io.vn 0/10 (markdown content type).
- `bun test ./tools`: **178 pass, 0 fail** (no code changed; nothing regressed).
- `bun tools/patterns.mjs --check <domain>` for every site with a pattern file (numbers above).
- Per-site `curl -sL -m 20 -A "<catalog UA>"` spot checks as listed in the table (status + `<title>` only; no page
  body printed, no disallowed path fetched — robots.txt checked first for every host).
- Soft-404 probes with `zz-design-tools-probe-404` per template family: 404 everywhere except tailark
  (any slug 200s with a slug-derived title → engine "blind", see note) and soralabs `/motion/*` (200 + generic
  title); all other templates' probes were real 404s.
- Request budget: 3–6 requests per site for the look (entry, robots, home/listing; five sites got one repeated
  look pass), plus the 5–6 spot/probe requests named in the table, plus the engine's own `--check` sample
  (9–25 requests per domain, `tools/registry-urls.mjs`, sanctioned by the brief); one sitemap fetch for the moved
  site's new domain, one for `ui.soralabs.studio`. No path outside robots.txt's allow set was fetched.

## Unsure / for the coordinator

- **tailark — decide the guard question.** By hand the 28 `/blocks/quartz/<kind>` pages are real component
  pages; the engine refuses them because the site echoes any slug into the 200 page's `<title>` (probe verdict
  "blind"). Suggested carve-out: when the candidate url is in the site's own sitemap (`catalog/corpus/sites/
  tailark.com/sitemap.json` lists exactly the 28 kind pages), trust it even if the probe echoes. Otherwise
  tailark stays url-less — the config is left in place, it attaches nothing wrong either way.
- **soralabs — Accept header.** The engine's `accept: …text/plain;q=0.9…` makes Mintlify serve
  `text/markdown` for `/ui/base/<name>` and `/motion/<name>` (plain `text/html` gets the html page), so
  `judge()` misses the 8 `base-*` pages. Dropping `text/plain` from the engine's Accept, or reading the
  markdown twin, would fill them; the route A pattern is unaffected (it never fetches).
- **tailark variant pages.** The visible page payload attributes every Quartz variant to its kind page; the
  rendered grid itself was not inspected (the /view/<name> previews are robots-disallowed). If the grader wants
  per-variant pages, tailark cannot provide them under robots.
- **shadcn-map**: the `shapes` rule maps six variant names onto one page; I verified the page exists and is
  named "Shapes", not that each shape variant is rendered there.
- **launchui**: the engine's sample showed `glow`, `mockup` and `badge` passing via `/docs/components/<name>`,
  so more of the 8 ui items may fill than the 17 I counted by hand.
- **soralabs**: `/ui/radix/<name>` vs `/motion/<name>` for the primitive items is decided by sitemap order, not
  by my template order (both are real component pages; files path is `registry/primitives/…`).
- **flexnative**: 1 item was left `unfinished` (a transient) in the engine's 10-item sample — expected; the
  resume run retries it.
- The batch table's url-less counts differ slightly from the current `catalog/items` for a few sites (shuip 52
  vs 48 target-type items, 7ovr 243 vs 244); the table uses the batch table's numbers.
