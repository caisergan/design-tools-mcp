# Brief 16d — registry url routes for the d-batch (18 sites) — Report

Branch `phase6/registry-tpl-d`, 2026-10-10. Files added: 16 `catalog/registry-urls/<domain>.json`
(12 template configs + 4 skips) and 2 `catalog/patterns/<domain>.json`. No code touched; `bun test ./tools`
passes (178 pass, 0 fail). All curl checks used the catalog UA, `-m 12..20`, and only status/`<title>`.

## Method

The engine (`tools/registry-urls.mjs`) does not exist on this branch, so every route was established by hand:
offline comparison of registry names against the corpus sitemap, the site's own registry metadata where it carries
page hints (shadcnuikit `href`, mynaui `docs`), and live `curl` probes of candidate pages including one made-up name
(`zz-design-tools-probe-404`) per template. Configs were validated offline: JSON, JS regex compile, `https` +
`{name}` template, and "each url-less item matches exactly one rewrite rule or none" (so both chained and
first-match-win rewrite semantics give the same result).

## Things I was unsure about

- **Group pages without anchors.** shadcnuikit, mynaui, shadcnstore, efferd, beui, reui, remocn and clerk all land
  several variants on one group page (the brief allows this, `note` in each file says so). The page anchors
  (`#hero-sections-1`, `#app-shell-1`) exist but are deliberately not used, so a hit is one fetch per item and
  cannot look like a redirect the template did not produce.
- **ui.aceternity `grid`** → `/components/grid-and-dot-backgrounds`: the page title names the component but its
  install blocks name the demo items (`@aceternity/grid-background-demo`), not `@aceternity/grid`; kept because
  the page is the only grid page, but it is the weakest mapping in the batch.
- **clerk.com** page/file types: including them goes beyond the batch's four default types (needed to reach the
  batch's own 11-item count). If the coordinator prefers the strict defaults, the 4 `registry:page` rules simply
  won't be tried.
- **`remocn.dev` / `sv-blocks.vercel.app`** add only +3 / +6 through registry-urls; the rest of their url-less
  items were probed and have no page (their existing patterns keep attaching the 104 / 75 they did before).
- **dotmatrix / simple-ai** are skips for soft-404/redirect reasons (probe evidence in the table), not for lack of
  trying: both have plausible per-item URLs (`/playground?loader=<name>`, `/docs/components/<name>`) that cannot
  pass the engine's own guards.
